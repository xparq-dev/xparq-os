Architecture Deep Dive
ฉันกำลังพัฒนา XPARQ OS บน Zircon Kernel ซึ่งใช้ object-capability security model อธิบายให้ฉันเข้าใจลึกว่า capability-based access control ต่างจาก Unix permission model (DAC) อย่างไรในระดับ kernel implementation พร้อม trade-off ด้าน performance และ security surface area

ARM vs x86 Architecture Comparison
XPARQ OS ต้องรองรับทั้ง ARM และ x86-64 เปรียบเทียบ privilege model ระหว่าง ARM Exception Level (EL0–EL3) กับ x86 Protection Ring (Ring 0–3) อย่างละเอียด: วิธีที่ Zircon Kernel จัดการ architecture-specific code path, ABI differences, และ porting strategy ที่ทำให้ XPARQ OS รองรับสองสถาปัตยกรรมโดยใช้ codebase เดียวกัน
// ใช้เมื่อ: วางแผน multi-arch strategy ของ XPARQ OS
COPY
Memory Model Internals
ใน Zircon Kernel, Virtual Memory Object (VMO) และ Virtual Memory Address Region (VMAR) ทำงานร่วมกันอย่างไร เปรียบเทียบกับ Linux mmap() และ anonymous mapping อธิบาย memory lifecycle ตั้งแต่ untyped memory → VMO → mapped region พร้อม implication ต่อ XPARQ OS memory architecture บนทั้ง ARM (LPAE) และ x86-64 (PML4 page table)
